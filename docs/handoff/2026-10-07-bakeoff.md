# Handoff 2026-10-07 — quality bake-off: blox vs the article workflow

Paste the prompt at the bottom into a fresh session.

## Why

The user asked whether blox is worth continuing. Their measure is **the quality of the work produced**, not
whether blox has a feature. The 2026-10-05 comparison (`bench/results/claude-vs-blox-2026-10-05.md`) only
measured pass/fail, turns and cost on small tasks: 17/17 for every side. It never judged quality. This bake-off
does.

## Arms (same model: Opus 5.5 on subscription; same prompts, references and budget)

- **A — the article workflow.** Claude Code with the official Roblox Studio MCP and
  [robloxstudio-mcp](https://github.com/Chrrxs/robloxstudio-mcp) (MIT). No blox. A follows every practice from
  the article the user shared (summary in memory `article-workflow-takeaways.md`):
  - Code lives in files, synced with Rojo. The empty project must pass 4 checks before any game code is
    written: `rojo build`, tests (pure rules, run without Roblox, e.g. Lune), selene lint, stylua format.
  - 4 rules: code in files not Studio; every number in one config folder; every client/server message goes
    through one remotes file; a written list of traps.
  - Rules (damage, costs, upgrades) are plain numbers with no Roblox objects, so they test without Studio.
  - UI: one spec makes three things: a preview image, the UI file and the Studio build script. Every panel
    and button gets the "depth stack": a blue-shifted shadow, a face gradient, top lift and an even outline.
    A checker runs at 4 screen sizes (small phone up to 1080p): thumb-size tap targets, nothing touching,
    centred items within 1.5 px, no text too small, no stray boxes around buttons.
  - Icons and images come from an AI image model (no emoji). The article used Flux schnell on Cloudflare
    Workers AI; the user wants to try hosting an open model (e.g. Qwen-Image) on **Kaggle** GPU. 3D comes
    from Hunyuan3D on Kaggle, reduced to ~6k triangles in headless Blender, with the detail baked back in as
    a texture. Hard-edged props (crates, guns) are built directly in Blender. Uploads go through Open Cloud.
  - Maps: measure movement with raycasts and real jump/speed numbers from config, each number labelled with
    its source and guesses listed. The 9 checks: floating platforms, tops you can't stand on, unreachable
    high ground, places a player can reach but shouldn't, pockets you can fall into and never climb out of,
    sightlines too open or closed, parts stuck inside each other, uneven rings, ragdoll shortfalls.
  - VFX/SFX (if needed): harvest free packs → classify → building blocks; "phase freeze" (freeze particles
    at start/middle/end) to judge an effect.
- **B — blox.** Claude Code with blox (`node ~/blox/dist/cli.js`, MCP `blox mcp`) and the official Studio
  MCP, as blox is today. No new blox features during the bake-off.

If A wins only because of a tool blox lacks (e.g. AI icons), record it as "tooling", separate from
"workflow". Either way it goes on the blox gap list.

## Judging

- **Blind, by the user.** After both arms finish, a neutral script (not either arm) captures the same shots
  from each place: the map from 6 fixed cameras plus a top-down view, edit and play; the UI at phone
  portrait, phone landscape, tablet and 1080p, in states Shop (locked/next/owned) and the confirm dialog.
  Label the sides X/Y by coin flip, build one sheet per task, and show the user. **Reveal the arms only
  after they pick.**
- **Objective, by Claude:** walkability (BFS over a raycast grid with the real jump height 7.2 and
  WalkSpeed 16: every area a player should reach is reachable; every dog spawn reaches the player spawns);
  part and triangle counts; server/client frame time with 40 moving dummies; UI overlap, tap targets, text
  size; script errors in the output; and code quality (in files? tests? config in one place? rebuildable
  from disk?).
- Report cost, turns and wall time beside quality, not instead of it.
- **Decision rule:** if A matches or beats B on quality in both tasks, stop building blox and keep only what
  clearly helped (write the list). If B wins, continue blox and port A's winning practices into it.
  Write `bench/results/quality-bakeoff-<date>.md` and PR + merge it in ~/blox.

## Setup and prerequisites

- **Scratch places only.** Create `~/bakeoff/a` and `~/bakeoff/b`, each with its own fresh Studio place
  (e.g. `BakeoffA.rbxl`, `BakeoffB.rbxl`). Never touch `DogAttack.rbxl` during the bake-off. Run one arm at a
  time with only that arm's place open, so the MCP servers can't hit the wrong place.
- **robloxstudio-mcp (approved by the user):** add it for arm A only (project scope in `~/bakeoff/a`):
  `claude mcp add robloxstudio -- npx -y @chrrxs/robloxstudio-mcp@latest --auto-install-plugin`. It installs
  a Studio plugin on Windows. Fully close and reopen Studio until the plugin shows **Connected**. Read its
  `docs/configuration.md` first (HTTP bridge, Studio settings, WSL→Windows port). It can be removed afterwards.
- **Kaggle:** the CLI is at `~/miniforge3/bin/kaggle` (1.7.4.5), but `~/.kaggle/kaggle.json` is rejected
  (`401 Unauthorized`). The user must create a new API token (kaggle.com → Settings → API → Create New Token)
  and save it as `~/.kaggle/kaggle.json` (chmod 600). Kaggle notebooks are batch jobs with weekly GPU quotas;
  serving a model from one is fragile and may conflict with Kaggle's terms, so check the terms first. Prefer
  running image/3D generation as batch notebook jobs (push a notebook with `kaggle kernels push`, poll, pull
  the outputs) over a live tunnelled server. If Kaggle can't be used, fall back to Cloudflare Workers AI
  Flux schnell (needs the user's Cloudflare account ID + API token) and say so in the report.
- **Uploads** (Open Cloud) and asset approvals are authorized for the bake-off. Never create, price or
  publish passes/products, and never publish a place.
- Each arm runs as its own `claude -p` (or interactive) session in its own directory, with only its own MCP
  servers configured (`--mcp-config ... --strict-mcp-config`), so arm A can't see blox and arm B can't
  see robloxstudio-mcp. Capture stream-json logs for turns/cost. A existing bench agent
  `claude-code-studio` in ~/blox shows how a plain arm is wired.
- Restore the Studio window yourself if it is minimised. Don't run multiplayer tests while the user is
  playing Roblox on this PC.
